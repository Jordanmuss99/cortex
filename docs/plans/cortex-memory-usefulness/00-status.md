## Notes for a fresh session

- The August 2026 audit concluded that Cortex persists and sometimes retrieves useful memories, but does not yet reliably capture new information, return current context, or demonstrate that memory improves task outcomes.
- The primary product outcome is measurable improvement on real memory-dependent work, rather than higher storage volume or retrieval-only benchmark scores.
- All four gates were explicitly approved on 2026-08-28. Implementation is now proceeding one approved vertical slice at a time.
- Gate 3 review exposed missing Gate 2 data contracts for atomic feedback, durable operation evidence, content-free daily rollups, database-enforced memory ownership, synthesis provenance, and the human-scored evaluation path. Gate 2 was reopened rather than silently introducing them later.
- The completed Gate 3 contract preserves legacy REST/MCP recall shapes, attributes health facts to their producing build/version, separates item harm from known outcome harm, expires generated artifacts non-destructively, and makes the six-arm human evaluation resumable, blinded, immutable, and complete-set checked.
- Slice 1 is complete. It adds the validated shared memory configuration boundary, a deliberately health-only first `MemoryServices` vertical subset, shared root probes, build attribution, and fail-closed REST startup gating. Later slices extend the service/dependency interfaces only when each service works end to end; unusable placeholder services were intentionally not published.
- During database unreachability, the real REST process exposes `/livez`, keeps `/readyz` at the Slice 1 mock `not_ready`, closes all application routes, and retries with capped backoff. Reachable missing or checksum-invalid migrations still exit before listening, preserving the OAuth migration invariant.

Real-process curl returned `200 {"status":"ok"}` for `/livez`, `503 {"status":"not_ready"}` for `/readyz`, and `503` for application routes during a simulated database outage; malformed JSON could not break liveness.

- Slice 4 is complete. A distinct event can reuse a projection only when same-agent, current, event-backed content has the same normalized chunk, fact validity, effective priority, final entities/tags, derivation discriminators, projection version, and embedding provider/model. Source identity remains separate provenance; forced, legacy, foreign-agent, expired, and metadata-mismatched projections are not reused.
- `replace_source` now orders snapshots by immutable acceptance time plus event ID under a source lock. Finalization uses a database transaction timestamp clamped to acceptance and prior indexing evidence; late work is safely rejected, while failed or merely queued refreshes leave the last indexed snapshot current. Replacement closes prior event evidence atomically and retires only nodes with no other open indexed support, including legacy same-source rows only after the first managed refresh commits.
- Markdown, Telegram, Limitless, corpus, watcher, and MCP file/corpus paths now submit stable whole-file snapshot events. File identity combines canonical path, descriptor metadata, and content hash, so retries replay but an A-to-B-to-A restore becomes a new version. Reads are root-confined, byte-bounded, symlink-safe during discovery, and revalidate descriptor/path identity after reading; empty, changing, outside-root, and oversized inputs cannot evict the last good snapshot.
- Corpus submission is concurrency-bounded, durably accepts every readable file before one optional globally bounded wait, caps receipt summaries, separates queued/indexed/failed/rejected outcomes, and never counts queued work as indexed chunks. Watcher and MCP responses retain event IDs and distinguish queued, indexed, terminal failure, and obsolete states; the generic `cortex_ingest` writer remains assigned to Slice 5.
