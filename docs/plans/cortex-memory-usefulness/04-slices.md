# Vertical Slices: Cortex Memory You Can Trust

## Build rule

Migration 010 is rechecked against the live migration namespace before Slice 2. Until Slice 18 freezes its checksum, every schema-dependent proof runs only against the guarded disposable PostgreSQL database; no intermediate form of migration 010 is applied to production. Every slice ends with its named focused tests plus the relevant pre-existing regression tests, a runnable curl/MCP/script proof where applicable, and a review checkpoint before the next slice.

## Slices

1. **Tracer bullet — shared runtime and probes** — add the transport-neutral config/service shell, mount `/livez` and a deliberately mocked `not_ready` `/readyz` through the real REST process, and prove both with focused tests and curl without changing memory behavior.
2. **Real happy path — durable REST capture to searchable projection** — add the first migration-010 lifecycle subset, operation heartbeat, ingest service, worker, REST accept/status adapters, and guarded database harness so one curl request is durably accepted, indexed once, becomes searchable, and makes readiness real.
3. **Capture survives failure and concurrency** — add stable canonical idempotency, lease recovery, projection checkpoints, provider-result validation, sanitized retries/dead letters, same-agent constraints, and the operator retry command; prove crashes and concurrent retries neither lose nor duplicate memory.
4. **Source snapshots remain current without destructive replacement** — add exact projection reuse plus ordered `replace_source` semantics and move markdown, Telegram, Limitless, and watcher ingestion onto it; prove late/failed refreshes cannot evict the last good snapshot.
5. **Every production writer uses durable acceptance** — route MCP ingest, gateway/session capture, reflection, screen observation, and multi-reflection through the same stable event contract; prove distinct facts are retained, exact retries replay, and queued work is never reported as indexed.
6. **Read-only hybrid search with evidence IDs** — add retrieval persistence, lexical/vector/entity lanes, current/agent filtering, deterministic rank fusion, optional-valid CA3 candidates, REST/MCP search adapters, and the compatibility wrapper; prove only delivered results become labile and candidacy mutates nothing.
7. **Bounded working context at session boot** — add working-set persistence/service/private routes, journal and strategic-thread reconciliation, the working retrieval lane, and working-first `cortex_init`; prove bounds, expiry/resolution, and that stale protected storage cannot monopolize boot.
8. **Budgeted recall and artifacts stay compatible and measurable** — move REST/MCP recall to the shared pack/deliver flow, instrument active artifacts, add the untrusted evidence envelope, and preserve exact legacy fields and the 256–32,000 token contract; prove every exposed item has a delivered retrieval-item ID.
9. **Honest feedback and task outcomes close the utilization loop** — add immutable feedback/outcome persistence and the private adapter, then wire MCP, gateway, hooks, and evaluator-facing callers to report only observed injection/use/citation/correction/harm; prove unknown stays unknown and confirmed use increments once.
10. **Corrections become append-only versions** — replace in-place reconsolidation with durable successor projection, atomic predecessor closure, provenance, correction artifacts, and a bounded correction working item; prove failure and concurrent corrections never erase or fork current memory.
11. **Vitals report real lifecycle health** — add build-attributed operation evidence, capture/index/retry latency, retrieval/error/utilization/harm coverage, scheduler freshness, graph distributions, shared readiness, and thin REST/MCP/self-check adapters; prove quiet ad-hoc sources and missing feedback are labelled unknown rather than healthy or failed.
12. **Telemetry ages safely without losing trends** — add content-free per-day/build/version rollups, all-partition watermarks, 30/365-day detail retention, query/correlation redaction, cognitive-artifact origins/status, and non-destructive artifact expiry; prove deletion aborts before complete rollup and durable memory survives artifact expiry.
13. **Dream uses demonstrated utility and forgets conservatively** — switch resonance to bounded auditable components, enforce the 30-day/100-feedback rollout guard, archive only strongly evidenced unused P3/P4 projections, protect P0/P1 and unknown utility, disable synthesis by default, and require provenance/expiry when enabled.
14. **Native long-lived MCP replaces the process-per-session bridge** — export the per-session server factory, add bounded Streamable HTTP POST/GET/DELETE sessions and shared probes/pool, preserve stdio/tool schemas, update container wiring, and prove session isolation, cleanup, metadata-only logs, and warm latency.
15. **Legacy diagnostics and benchmarks cannot corrupt lifecycle state** — adapt novelty/backfill utilities, cleanup reports, CogBench, LoCoMo/LongMemEval clients, reconsolidation, and cross-agent transfer to disposable lifecycle-aware helpers; prove no benchmark can target production or reward mutation-based semantics.
16. **Causal evaluation executes six isolated conditions safely** — add evaluation persistence, locked dataset/manifest validation, self-validating comparison groups, fixed clocks, explicit gold bindings, disposable per-case agents/database, common executor contracts, redacted results, seeded cluster scoring, and a synthetic six-condition run that cannot claim Product success.
17. **Blinded human adjudication makes Product scoring resumable** — add hash-bound packet export/import, exact 0–4 rubric aggregation, pending-only execution writes, immutable human completion, complete-case/digest checks, bootstrap confidence intervals, and replay-safe finalization; prove an interrupted synthetic run resumes without model reruns and still cannot pass.
18. **Release candidate freezes the migration and compatibility contract** — recheck/freeze migration 010 and runtime grants, run unit/typecheck/build/OAuth/memory/database/MCP suites together, exercise the composed worker/REST/native-MCP stack, verify all legacy wire contracts, and finish operator/contributor/benchmark/technical documentation.
19. **Real Product acceptance measures usefulness** — lock and independently attest at least 200 representative memory-dependent holdout tasks, run all six conditions, complete at least 400 blinded primary judgments, and publish the redacted report; Cortex is called useful only if every pair is complete, uplift is at least 15.0 points, and the 95% interval is present.

## External acceptance dependency

Slices 1–18 can finish with repository-controlled synthetic and integration evidence. Slice 19 additionally requires the private representative task set, independent sampling review, model/provider access, and human-adjudication capacity; absence of those inputs blocks the Product claim but does not permit a synthetic or model-judged substitute.
